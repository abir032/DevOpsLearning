By now QuickCart's platform exists because people clicked it into being. Priya knows how the network was built. Sam remembers the target group's drain setting. Nobody remembers everything, and the notes are already out of date.

Then someone asks the question every team dreads: "If we lost this account tonight, how long to rebuild it?" The honest answer is "days, and it would come back different".

In this project you make that answer "about thirty minutes, and identical". You rebuild Projects 1 to 3 as Terraform code: modules for each piece, remote state with locking, two environments that differ only in their values, and a copy in a second region. Then you prove it: destroy everything, build it again from empty with no clicks, and show that the next plan has nothing left to do.

## What you'll have at the end

<ThreeStacks />

**What to notice:** switch between the three environments and watch the code column. It never changes. Only the values and the state file's key do, and those few values decide how many NAT gateways, tasks and database copies get built.

The repository looks like this:

```text title="quickcart-infra/"
quickcart-infra/
├── .gitignore
├── shared/                 built once per account: the image repositories
│   └── main.tf
├── modules/                reusable pieces that never mention an environment
│   ├── network/main.tf     VPC, three tiers of subnets, NAT, routes, S3 endpoint
│   ├── security/main.tf    the load balancer → app → database chain
│   ├── certificate/main.tf self-signed, or trusted if you own a domain
│   ├── alb/main.tf         load balancer, stable and canary target groups
│   ├── ecs-service/main.tf one ECS service with its task definition and logs
│   ├── data/main.tf        MySQL on RDS, and a private S3 bucket
│   ├── alarms/main.tf      the three alarms from Project 2
│   └── eks/main.tf         cluster, nodes, and the controller's permissions
├── stack/                  one whole environment: calls every module
│   ├── variables.tf
│   ├── main.tf
│   ├── eks.tf
│   └── outputs.tf
└── envs/                   one folder per environment, each with its own state
    ├── dev/                main.tf, backend.tf, terraform.tfvars
    ├── prod/               the same main.tf; its own backend.tf and values
    └── dev-usw2/           the same main.tf; the second region
```

| Folder | Its job | Rule |
|---|---|---|
| `shared/` | things one account needs once: ECR repositories and replication | applied once, before any environment |
| `modules/` | one piece of infrastructure each | never mentions `dev` or `prod`, so it can be reused |
| `stack/` | one complete environment, built from the modules | takes every difference as a variable |
| `envs/<name>/` | where you run Terraform | `main.tf` is an identical copy everywhere; only `backend.tf` and `terraform.tfvars` differ |

| Project | What it becomes in code |
|---|---|
| [Project 1](/projects/01-network-by-hand/): the network | `modules/network` and `modules/security`, plus least-privilege roles in `stack/` and `modules/eks` |
| [Project 2](/projects/02-self-healing-environment/): the self-healing environment | `modules/alb`, `modules/data`, `modules/alarms`, and the database secret. The order service now runs as containers, so the ECS service replaces the EC2 auto scaling group and does the same job: it replaces failed copies across two zones |
| [Project 3](/projects/03-one-service-two-runtimes/): one service, two runtimes | `modules/ecs-service` twice (stable and canary), `modules/eks`, and the Kubernetes objects in `stack/eks.tf` |

Unlike Project 3, the containers now run in **private** app subnets behind NAT gateways, as in Project 1. The canary service and target group are built now, idle, so [Project 5](/projects/05-the-pipeline/)'s pipeline has somewhere to send a canary.

## The shared layer

Images are build artifacts, not infrastructure: they come from a build, not from Terraform. But the repositories that hold them are infrastructure, and every environment needs them before it starts. So they live in their own small layer, applied once, with their own state.

<Steps>

<Step title="Write shared/main.tf">

```hcl title="shared/main.tf" ph="111122223333"
terraform {
  required_version = ">= 1.10.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }

  backend "s3" {
    bucket       = "quickcart-tfstate-111122223333"
    key          = "shared/terraform.tfstate"
    region       = "us-east-1"
    encrypt      = true
    use_lockfile = true
  }
}

provider "aws" {
  region = "us-east-1"

  default_tags {
    tags = {
      Project   = "quickcart"
      ManagedBy = "terraform"
    }
  }
}

locals {
  repositories  = toset(["quickcart-orders", "quickcart-ops"])
  second_region = "us-west-2"
}

data "aws_caller_identity" "current" {}

resource "aws_ecr_repository" "main" {
  for_each = local.repositories

  name                 = each.key
  image_tag_mutability = "IMMUTABLE"
  force_delete         = true

  image_scanning_configuration {
    scan_on_push = true
  }
}

resource "aws_ecr_repository" "second_region" {
  for_each = local.repositories

  region               = local.second_region
  name                 = each.key
  image_tag_mutability = "IMMUTABLE"
  force_delete         = true

  image_scanning_configuration {
    scan_on_push = true
  }
}

resource "aws_ecr_lifecycle_policy" "main" {
  for_each = aws_ecr_repository.main

  repository = each.value.name
  policy = jsonencode({
    rules = [{
      rulePriority = 1
      description  = "Keep the 30 newest images"
      selection = {
        tagStatus   = "any"
        countType   = "imageCountMoreThan"
        countNumber = 30
      }
      action = {
        type = "expire"
      }
    }]
  })
}

resource "aws_ecr_replication_configuration" "main" {
  replication_configuration {
    rule {
      destination {
        region      = local.second_region
        registry_id = data.aws_caller_identity.current.account_id
      }

      repository_filter {
        filter      = "quickcart-"
        filter_type = "PREFIX_MATCH"
      }
    }
  }

  depends_on = [aws_ecr_repository.second_region]
}

output "repository_urls" {
  description = "Where to push images, in the main region"
  value       = { for name, repo in aws_ecr_repository.main : name => repo.repository_url }
}
```

The `terraform` block, `required_providers` and the `backend "s3"` settings are explained in [Terraform state](/lessons/terraform-state/). This layer's `key` is `shared/terraform.tfstate`, so it can never touch an environment's state. The `repository_urls` output is explained in [Variables, locals and outputs](/lessons/terraform-variables/).

| Setting | What it does | If you leave it out | When you'd change it |
|---|---|---|---|
| `provider "aws"` → `default_tags` | adds `Project` and `ManagedBy` tags to **every** resource this provider creates | resources have no tags unless each one sets them; costs are hard to trace | add an owner or cost-centre tag |
| `local.repositories` | the two repositories: the order service, and the operations tool Project 5 builds | — | add one line per new service |
| `data "aws_caller_identity"` | reads your account ID, so no account number is typed into the code | you'd hard-code `111122223333`, and the code would break in another account | never |
| `aws_ecr_repository.main` → `for_each` | one repository per name in the list | — | — |
| `image_tag_mutability = "IMMUTABLE"` | a tag, once pushed, can never point at a different image | defaults to `MUTABLE`: `v1` could quietly mean different code tomorrow | never, for release images |
| `force_delete = true` | lets `terraform destroy` delete a repository that still holds images | destroy fails while any image is inside | set to `false` once a repository holds images you can't rebuild |
| `image_scanning_configuration` → `scan_on_push` | scan every image for known security problems as it arrives | no automatic scan | never |
| `aws_ecr_repository.second_region` → `region` | creates the same repositories in `us-west-2`. Setting `region` on one resource is new in AWS provider 6; before, you needed a second provider block with an `alias` | the replicated images would land in repositories that Terraform doesn't manage, and `destroy` would leave them behind | when you pick a different second region |
| `aws_ecr_lifecycle_policy` | deletes all but the 30 newest images in each repository | images pile up forever, and storage slowly costs more | keep more if you need to roll back further |
| `policy = jsonencode({...})` | writes the lifecycle rule as JSON from HCL, so a typo is caught by Terraform, not by AWS | — | — |
| `aws_ecr_replication_configuration` | copies every image pushed to a `quickcart-` repository into the same repository in `us-west-2` | you'd push every image twice, by hand: a manual step | when the second region changes |
| `repository_filter` → `PREFIX_MATCH` `"quickcart-"` | only these repositories are copied | every repository in the account is copied | — |
| `depends_on = [aws_ecr_repository.second_region]` | make the destination repositories before turning replication on | the first replicated push could create an unmanaged repository | never |

</Step>

## The modules

Each module is one folder with one `main.tf`: its inputs (`variable` blocks), its resources, and its outputs. A module never knows which environment it's in. Everything that could differ comes in as a variable, with a `description` that says why it exists. [Modules](/lessons/terraform-modules/) explains the idea.

<Steps>

<Step title="The network">

```hcl title="modules/network/main.tf"
variable "name" {
  description = "Prefix for every name, like quickcart-dev"
  type        = string
}

variable "cidr" {
  description = "The VPC's address range. Each environment and region needs its own, so they can be connected later"
  type        = string

  validation {
    condition     = can(cidrhost(var.cidr, 0)) && endswith(var.cidr, "/16")
    error_message = "Use a /16 range, like 10.20.0.0/16."
  }
}

variable "single_nat_gateway" {
  description = "One NAT gateway for both zones. Cheaper, but the app subnets in the second zone lose outbound internet if the first zone fails"
  type        = bool
}
data "aws_availability_zones" "available" {
  state = "available"
}

data "aws_region" "current" {}

locals {
  azs     = slice(data.aws_availability_zones.available.names, 0, 2)
  zones   = { for i, az in local.azs : az => i }
  nat_azs = var.single_nat_gateway ? slice(local.azs, 0, 1) : local.azs
}

resource "aws_vpc" "this" {
  cidr_block           = var.cidr
  enable_dns_support   = true
  enable_dns_hostnames = true

  tags = { Name = "${var.name}-vpc" }
}

resource "aws_subnet" "public" {
  for_each = local.zones

  vpc_id                  = aws_vpc.this.id
  cidr_block              = cidrsubnet(var.cidr, 8, each.value)
  availability_zone       = each.key
  map_public_ip_on_launch = true

  tags = {
    Name                     = "${var.name}-public-${each.key}"
    "kubernetes.io/role/elb" = "1"
  }
}

resource "aws_subnet" "app" {
  for_each = local.zones

  vpc_id            = aws_vpc.this.id
  cidr_block        = cidrsubnet(var.cidr, 8, each.value + 10)
  availability_zone = each.key

  tags = {
    Name                              = "${var.name}-app-${each.key}"
    "kubernetes.io/role/internal-elb" = "1"
  }
}

resource "aws_subnet" "data" {
  for_each = local.zones

  vpc_id            = aws_vpc.this.id
  cidr_block        = cidrsubnet(var.cidr, 8, each.value + 20)
  availability_zone = each.key

  tags = { Name = "${var.name}-data-${each.key}" }
}

resource "aws_internet_gateway" "this" {
  vpc_id = aws_vpc.this.id

  tags = { Name = "${var.name}-igw" }
}

resource "aws_eip" "nat" {
  for_each = toset(local.nat_azs)

  domain = "vpc"

  tags = { Name = "${var.name}-nat-${each.key}" }
}

resource "aws_nat_gateway" "this" {
  for_each = toset(local.nat_azs)

  allocation_id = aws_eip.nat[each.key].id
  subnet_id     = aws_subnet.public[each.key].id

  tags = { Name = "${var.name}-nat-${each.key}" }

  depends_on = [aws_internet_gateway.this]
}

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.this.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.this.id
  }

  tags = { Name = "${var.name}-public" }
}

resource "aws_route_table" "app" {
  for_each = local.zones

  vpc_id = aws_vpc.this.id

  route {
    cidr_block     = "0.0.0.0/0"
    nat_gateway_id = aws_nat_gateway.this[var.single_nat_gateway ? local.nat_azs[0] : each.key].id
  }

  tags = { Name = "${var.name}-app-${each.key}" }
}

resource "aws_route_table" "data" {
  vpc_id = aws_vpc.this.id

  tags = { Name = "${var.name}-data" }
}

resource "aws_route_table_association" "public" {
  for_each = aws_subnet.public

  subnet_id      = each.value.id
  route_table_id = aws_route_table.public.id
}

resource "aws_route_table_association" "app" {
  for_each = aws_subnet.app

  subnet_id      = each.value.id
  route_table_id = aws_route_table.app[each.key].id
}

resource "aws_route_table_association" "data" {
  for_each = aws_subnet.data

  subnet_id      = each.value.id
  route_table_id = aws_route_table.data.id
}

resource "aws_vpc_endpoint" "s3" {
  vpc_id            = aws_vpc.this.id
  service_name      = "com.amazonaws.${data.aws_region.current.region}.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = [for rt in aws_route_table.app : rt.id]

  tags = { Name = "${var.name}-s3" }
}
output "vpc_id" {
  description = "The VPC's ID"
  value       = aws_vpc.this.id
}

output "public_subnet_ids" {
  description = "One public subnet per zone, for load balancers and NAT gateways"
  value       = [for s in aws_subnet.public : s.id]
}

output "app_subnet_ids" {
  description = "One private app subnet per zone, for containers and Kubernetes nodes"
  value       = [for s in aws_subnet.app : s.id]
}

output "data_subnet_ids" {
  description = "One isolated data subnet per zone, for the database"
  value       = [for s in aws_subnet.data : s.id]
}
```

This is Project 1's network. The ideas are in [What is a VPC?](/lessons/vpc/), [Subnets and IP ranges](/lessons/subnets-and-cidr/) and [Routes, gateways and NAT](/lessons/routing/).

| Setting | What it does | If you leave it out | When you'd change it |
|---|---|---|---|
| `variable "cidr"` → `validation` | refuses anything that isn't a valid `/16`, before anything is built | a typo like `10.20.0.0/61` fails half-way through an apply | if you plan differently sized networks |
| `variable "single_nat_gateway"` | the cost trade-off from Project 1, written where it's decided | — | `true` in dev to save about $1 a day; `false` in prod |
| `data "aws_availability_zones"` → `state = "available"` | looks up the region's zone names instead of typing `us-east-1a` | hard-coded zone names break in any other region | never |
| `data "aws_region"` | reads the region this provider is using, for the S3 endpoint's name | you'd type the region into the module | never |
| `local.azs` → `slice(…, 0, 2)` | the first two zones, whatever the region calls them | — | three zones for more resilience, at the cost of a third NAT gateway in prod |
| `local.zones` | a map like `{ "us-east-1a" = 0, "us-east-1b" = 1 }`, so each subnet has a stable key and a number | — | — |
| `local.nat_azs` | one zone or both, from `single_nat_gateway` | — | — |
| `aws_vpc` → `cidr_block` | the VPC's address range | required | once per environment and region; never after it's built, because it replaces everything |
| `enable_dns_support`, `enable_dns_hostnames` | the VPC can resolve names, and resources get DNS names | RDS endpoints and VPC endpoints don't resolve properly | never |
| `tags = { Name = … }` | the name shown in the console. The provider's default tags are added too | the console shows a blank name | — |
| `aws_subnet` → `for_each = local.zones` | one subnet per zone, keyed by zone name. Why not `count`: see [Loops and lifecycle](/lessons/terraform-loops/) | — | — |
| `cidr_block = cidrsubnet(var.cidr, 8, …)` | carves a `/24` out of the `/16`: public gets `.0.` and `.1.`, app `.10.` and `.11.`, data `.20.` and `.21.` | you'd work out and type every range by hand | if a tier needs more than 251 addresses |
| `availability_zone = each.key` | which zone the subnet lives in | AWS picks, and two subnets could land in one zone | never |
| `map_public_ip_on_launch = true` (public only) | anything started here gets a public address | NAT gateways still work (they use an Elastic IP), but a public test instance couldn't be reached | never; nothing but the load balancer and NAT live here |
| `"kubernetes.io/role/elb" = "1"` | tells the EKS load balancer controller it may put internet-facing load balancers here: the tag you added by hand in Project 3 | the Ingress never gets an address | never |
| `"kubernetes.io/role/internal-elb" = "1"` | the same, for internal load balancers, on the app subnets | internal load balancers can't be placed | never |
| `aws_internet_gateway` | the VPC's door to the internet | nothing public works | never |
| `aws_eip.nat` → `domain = "vpc"` | a fixed public address for each NAT gateway | the NAT gateway has no address to use | never |
| `aws_nat_gateway` → `allocation_id`, `subnet_id` | which address it uses, and which **public** subnet it sits in | required | never |
| `depends_on = [aws_internet_gateway.this]` | build the internet gateway first. Nothing in the NAT gateway's settings points at it, so Terraform can't see the order | the NAT gateway can be created before the VPC can reach the internet, and fail | never |
| `aws_route_table.public` → `route` to the internet gateway | public subnets send `0.0.0.0/0` to the internet | the load balancer is unreachable | never |
| `aws_route_table.app` → `nat_gateway_id` | each app subnet sends outbound traffic to a NAT gateway: its own zone's, or the single one | containers can't reach ECR, so they can't start | never |
| `aws_route_table.data` with no routes | only the VPC's built-in `local` route: the database subnets can't reach or be reached from the internet | — | never |
| `aws_route_table_association` | attaches each subnet to its route table | the subnet uses the VPC's main route table | never |
| `aws_vpc_endpoint` → `vpc_endpoint_type = "Gateway"`, `service_name`, `route_table_ids` | S3 traffic from the app subnets goes straight to S3 instead of through the NAT gateway. Gateway endpoints are free; NAT traffic is not | S3 traffic costs NAT data charges | add interface endpoints (for ECR, Secrets Manager and logs) to drop the NAT gateway entirely, at about $7 a month each per zone |
| the four `output` blocks | the IDs other modules need | other modules can't find the subnets | — |

```hcl title="modules/certificate/main.tf"
  self_signed = var.domain_name == ""
}

resource "tls_private_key" "this" {
  count = local.self_signed ? 1 : 0

  algorithm = "RSA"
  rsa_bits  = 2048
}

resource "tls_self_signed_cert" "this" {
  count = local.self_signed ? 1 : 0

  private_key_pem       = tls_private_key.this[0].private_key_pem
  validity_period_hours = 2160
  allowed_uses          = ["key_encipherment", "digital_signature", "server_auth"]

  subject {
    common_name = "${var.name}.quickcart.test"
  }
}

resource "aws_acm_certificate" "imported" {
  count = local.self_signed ? 1 : 0

  private_key      = tls_private_key.this[0].private_key_pem
  certificate_body = tls_self_signed_cert.this[0].cert_pem

  tags = { Name = "${var.name}-self-signed" }

  lifecycle {
    create_before_destroy = true
  }
}

resource "aws_acm_certificate" "issued" {
  count = local.self_signed ? 0 : 1

  domain_name       = var.domain_name
  validation_method = "DNS"

  tags = { Name = var.name }

  lifecycle {
    create_before_destroy = true
  }
}

resource "aws_route53_record" "validation" {
  for_each = local.self_signed ? {} : {
    for dvo in aws_acm_certificate.issued[0].domain_validation_options : dvo.domain_name => dvo
  }

  zone_id         = var.zone_id
  name            = each.value.resource_record_name
  type            = each.value.resource_record_type
  records         = [each.value.resource_record_value]
  ttl             = 60
  allow_overwrite = true
}

resource "aws_acm_certificate_validation" "issued" {
  count = local.self_signed ? 0 : 1

  certificate_arn         = aws_acm_certificate.issued[0].arn
  validation_record_fqdns = [for r in aws_route53_record.validation : r.fqdn]
}

output "arn" {
  description = "The certificate for the load balancer's HTTPS listener"
  value       = local.self_signed ? aws_acm_certificate.imported[0].arn : aws_acm_certificate_validation.issued[0].certificate_arn
}
```

Two ways to get HTTPS, chosen by one variable. With `domain_name` empty, it makes the self-signed certificate you made with `openssl` in Project 3, with no manual step. With a domain you own in Route 53, it requests a trusted one and validates it by DNS. [Domain names and HTTPS](/lessons/dns-and-https/) explains the difference.

| Setting | What it does | If you leave it out | When you'd change it |
|---|---|---|---|
| `terraform` → `required_providers` → `tls` | this module uses the `tls` provider as well as `aws` | Terraform assumes `hashicorp/tls` anyway; saying so is clearer | never |
| `local.self_signed` | true when there's no domain | — | — |
| `count = local.self_signed ? 1 : 0` | build these resources in one mode and not the other. `count` is right here: it's on or off, never a list. See [Loops and lifecycle](/lessons/terraform-loops/) | both paths would be built | — |
| `tls_private_key` → `algorithm`, `rsa_bits` | a 2048-bit RSA key, the type ACM accepts | required | never |
| `tls_self_signed_cert` → `private_key_pem` | signs the certificate with that key | required | — |
| `validity_period_hours = 2160` | valid for 90 days | required | shorter for practice; a real site uses a trusted certificate |
| `allowed_uses` | what the certificate may be used for: a TLS server | required | never |
| `subject` → `common_name` | the name inside the certificate | the certificate has no name | — |
| `aws_acm_certificate.imported` → `private_key`, `certificate_body` | imports the pair into ACM, like the console's **Import** button | required for an import | — |
| `lifecycle` → `create_before_destroy` | when the certificate is replaced, make the new one first, so the listener always has one | Terraform deletes the old one first, and the listener refuses because it's in use | never |
| `aws_acm_certificate.issued` → `domain_name`, `validation_method = "DNS"` | requests a trusted certificate, proven by a DNS record | — | add `subject_alternative_names` for more names |
| `aws_route53_record.validation` → `for_each` over `domain_validation_options` | writes the record ACM asks for, one per name | the certificate waits forever in **Pending validation** | — |
| `zone_id`, `name`, `type`, `records`, `ttl` | where the record goes, and what it says | required | — |
| `allow_overwrite = true` | if a validation record already exists from an earlier try, take it over | the second apply fails because the record exists | never |
| `aws_acm_certificate_validation` | not a real AWS thing: a wait, until ACM says **Issued** | the listener could be given a certificate that isn't ready, and fail | never |
| `output "arn"` | whichever certificate was made | — | — |

<Note title="The private key is in the state file">

With the self-signed path, the certificate's private key passes through Terraform, so it's stored in state. That's acceptable for a practice certificate, and it's why the state bucket is encrypted and private. With the trusted path, ACM keeps the key and Terraform never sees it.

| `load_balancer_type = "application"` | an ALB, which understands HTTP | defaults to `application` | `network` for plain TCP |

| `health_check_grace_period_seconds = 30` | ignore failed health checks for 30 seconds after a task starts | a slow-starting task can be killed before it's ready | longer for slow starters |
| `deployment_minimum_healthy_percent = 100`, `deployment_maximum_percent = 200` | never go below the full count during a release; allow double | 100 and 200 are the defaults for a service like this; written so nobody changes them by accident | never |
| `deployment_circuit_breaker` → `enable`, `rollback` | a release whose tasks keep failing stops and goes back by itself | a broken release retries forever | never |
| `network_configuration` → `subnets`, `security_groups`, `assign_public_ip = false` | private app subnets, the app security group, no public address | required for `awsvpc` | never; NAT gives them their way out |
| `load_balancer` → `target_group_arn`, `container_name`, `container_port` | register each task's IP with the target group | no traffic reaches the tasks | — |
| `lifecycle` → `ignore_changes = [desired_count, task_definition]` | Terraform sets these **once**. After that, releases (Project 5's pipeline) change the task definition, and scaling changes the count | every release would show up as drift, and the next `apply` would roll production back to the image in Terraform | never, once a pipeline releases |
| the three outputs | names the pipeline and alarms need | — | — |

<Note title="Who owns what, from now on">

Because of `ignore_changes`, changing `image_tag` in a `.tfvars` file does **not** release anything once the service exists. That's deliberate. Terraform owns the shape of the platform; the pipeline owns which version runs. Mixing the two is how an innocent `terraform apply` rolls production back to last month's image.

</Note>

| Setting | What it does | If you leave it out | When you'd change it |
|---|---|---|---|
| `module "eks"` → `count` | builds the cluster only when `enable_eks` is true | — | — |
| `helm_release` → `repository`, `chart`, `version`, `namespace` | the same Helm install as Project 3, done by Terraform. The version matches the policy in `modules/eks` | — | together with the policy URL |
| `set = [{ name, value }, …]` | the `--set` values from Project 3's command | the controller can't find its cluster, region or VPC | — |
| `depends_on = [module.eks]` | install only once the nodes and permissions exist | the install waits for pods that can't schedule, then times out | never |
| `kubernetes_labels` → `api_version`, `kind`, `metadata`, `labels` | adds the readiness-gate label to the existing `default` namespace, as `kubectl label` did | new pods get no readiness gate, and releases can drop requests | never |
| `kubernetes_deployment_v1` | Project 3's Deployment, field for field: 2 replicas, `max_unavailable = 0`, `max_surge = 1`, the readiness probe, requests and limits, and the `preStop` sleep. HCL spells the YAML names in `snake_case` | — | — |
| `kubernetes_service_v1` | the fixed name in front of the pods | — | — |
| `kubernetes_ingress_v1` → `annotations` | the same annotations as Project 3; `certificate-arn` now comes from the certificate module | — | — |
| `wait_for_load_balancer = true` | `apply` waits until the controller has built the load balancer, so its address can be an output | the output would be empty on the first apply | never |
| `depends_on = [helm_release.lbc, …]` | create the Ingress after the controller, and delete it **before** the controller on `destroy`, so the controller is still running to delete its load balancer | the load balancer is left behind, still billing, and blocks the VPC's deletion | never |

<Note title="Providers configured from the thing they manage">

The `helm` and `kubernetes` providers (configured in each environment's `main.tf`) take their address from the cluster this same stack creates. Terraform handles that on a first build and on a full `destroy`. What it can't handle is switching `enable_eks` from `true` to `false` on an environment that has EKS: the providers lose their address before they can delete what's inside the cluster. To remove EKS, destroy the whole environment; see [Troubleshooting](#troubleshooting).

</Note>

## Troubleshooting

<Mistake title="the state bucket doesn't exist">

```output title="terraform init stops with a message containing"
S3 bucket "quickcart-tfstate-111122223333" does not exist.
```

**Why:** the bucket was deleted after the Terraform state lesson, or the name has the wrong account ID.

**The fix:** create it again as [Terraform state](/lessons/terraform-state/) shows, with versioning on, and check the name in every `backend.tf` matches it exactly.

</Mistake>

<Mistake title="tasks fail to start with a secrets error">

```output title="The ECS task's stopped reason starts with"
ResourceInitializationError: unable to pull secrets or registry auth
```

**Why:** the execution role can't read the database secret, or the tasks can't reach Secrets Manager. The first happens if the `read_db_secret` policy points at the wrong ARN; the second if the app subnets have no working route to a NAT gateway.

**The fix:** read the rest of the stopped reason. `AccessDeniedException` means the policy: check `terraform state show module.stack.aws_iam_role_policy.read_db_secret`. A timeout means the network: check the app route tables send `0.0.0.0/0` to a NAT gateway that's **Available**.

</Mistake>

<Mistake title="the second region's tasks can't find the image">

```output title="The stopped reason in us-west-2 says something like"
CannotPullContainerError: pull image manifest has been retried 7 time(s): failed to resolve ref 111122223333.dkr.ecr.us-west-2.amazonaws.com/quickcart-orders:v1: not found
```

**Why:** replication only copies images pushed **after** it was turned on. The `v1` image was pushed before `shared/` was applied. Your retry count may differ.

**The fix:** push the image again under a new tag, like `v1.1`, set `image_tag = "v1.1"` in both dev folders' values, and apply. Pushing is a build step, not infrastructure, so it doesn't count as a manual infrastructure step.

</Mistake>

<Mistake title="the second plan is never clean">

```output title="Every plan shows something like"
  # module.stack.module.orders["stable"].aws_ecs_service.this will be updated in-place
  ~ resource "aws_ecs_service" "this" {
      ~ desired_count = 3 -> 2
```

**Why:** something outside Terraform changes a value on purpose, and Terraform keeps trying to change it back. Here, scaling changed the task count. It's the same for a pipeline changing the task definition or the listener's weights.

**The fix:** decide who owns the value. If something else should, add it to that resource's `lifecycle` `ignore_changes`, as the ECS and load balancer modules do. If nothing should, find out who changed it: [Who changed what](/lessons/cloudtrail/) shows how, and [Operating Terraform](/lessons/operating-terraform/) covers drift.

</Mistake>

<Mistake title="destroy can't delete the VPC">

```output title="terraform destroy stops with an error containing"
DependencyViolation: The vpc 'vpc-0example1234567' has dependencies and cannot be deleted.
```

**Why:** something Terraform didn't create is still in the VPC. Almost always, it's a load balancer or security group made by the EKS load balancer controller, because the Ingress was removed after the controller was, or by hand.

**The fix:** in **EC2 > Load Balancers** and **EC2 > Security Groups**, filter by the VPC ID and delete anything whose name starts with `k8s-`. Then run `terraform destroy` again; it carries on where it stopped.

</Mistake>

<Mistake title="switching EKS off fails">

```output title="A plan after changing enable_eks to false stops with an error like"
Error: Get "http://localhost/api/v1/namespaces/default/services/orders": dial tcp [::1]:80: connect: connection refused
```

**Why:** the Helm and Kubernetes providers take the cluster's address from the stack. With `enable_eks = false`, that address is empty before the objects inside the cluster are deleted, so the providers fall back to `localhost` and can't reach the cluster to delete them. Your exact message may differ.

**The fix:** set `enable_eks` back to `true`, then `terraform destroy` the whole environment and apply it again with `false`. In dev that's a few minutes of rebuild, which is the point of this project.

</Mistake>

<Mistake title="destroying prod is refused">

```output title="terraform destroy stops with an error ending"
api error InvalidParameterCombination: Cannot delete protected DB Instance, please disable deletion protection and try again.
```

**Why:** that's `deletion_protection = true` doing its job.

**The fix:** in [Clean up](#clean-up).

</Mistake>

<Mistake title="a lock is held">

```output title="Any command stops with"
Error: Error acquiring the state lock
```

**Why:** another command is running against the same environment, or one crashed and left its lock behind.

**The fix:** read the `Who` and `Created` lines, check that nobody is really running Terraform, then `terraform force-unlock` with the lock's ID, as [Terraform state](/lessons/terraform-state/) shows.

</Mistake>
